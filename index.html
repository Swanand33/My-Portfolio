from llm_behave import assert_behavior, DriftTest

# semantic assertions, no judge model
def test_support_bot():
    output = my_support_bot("I want a refund for order 1234")

    assert_behavior(output) \
        .mentions("refund policy") \
        .tone("empathetic") \
        .not_mentions("competitor")

# fail CI when behaviour drifts
def test_no_regression():
    output = my_support_bot("I want a refund for order 1234")
    result = DriftTest.compare("support_refund_flow", output)
    assert result.passed

01 ContractIQ Independent contract Legal document review RAG / LLM application
Python · FastAPI · LangChain · Pinecone · PostgreSQL

Problem. Legal reviewers were spending significant time searching through long contract archives to locate specific clauses, definitions, and obligations. Keyword search also made it difficult to answer questions when the relevant information was expressed differently across agreements.

Build. Built a document-questioning system around section-aware ingestion and retrieval. Contracts were parsed into structured sections, metadata was attached by document and clause type, and embeddings were stored in a vector index. Retrieval was constrained using metadata and query context before passing the relevant sections to the LLM. Responses included source references so reviewers could verify the underlying text rather than relying on an unsupported model answer.

Outcome. Reduced the amount of manual searching required for first-pass contract review and gave reviewers a faster way to locate relevant clauses with a traceable source behind each answer.

02 FlowPilot Independent contract Operations workflow automation AI agent / automation
Python · FastAPI · LangGraph · OpenAI · PostgreSQL · REST APIs

Problem. A recurring operations process required people to collect information from multiple systems, interpret incoming requests, decide what action was needed, and then perform several follow-up steps manually.

Build. Built an agent-based workflow that first classified the incoming request, selected the appropriate tools, retrieved required information from internal APIs and databases, and then executed the relevant actions through a controlled workflow. State was persisted between steps so the system could handle multi-stage tasks rather than treating every request as a single LLM call. Added validation and fallback paths for cases where the model could not confidently determine the next action.

Outcome. Automated a repeatable portion of the workflow and reduced the amount of manual coordination required for routine requests, while keeping tool execution bounded to predefined actions rather than allowing unrestricted model behavior.

03 DataFlow Team project Data and ML platform Data engineering / ML pipeline
Python · SQL · Pandas · Airflow · PostgreSQL · scikit-learn · Docker

Problem. Data used for reporting and machine-learning workflows was coming from multiple sources with inconsistent formats, missing values, and different update schedules. Analysts and ML developers were repeatedly performing similar preparation work before they could use the data.

Build. Worked as part of a development team on a reusable data pipeline covering ingestion, validation, transformation, and feature preparation. Implemented Python-based processing and SQL transformations, added data-quality checks for common issues, and scheduled recurring pipeline runs through Airflow. Prepared curated datasets for downstream analytics and ML workflows and containerized components so the pipeline could be run consistently across environments.

Outcome. Replaced repeated manual data preparation with a structured, repeatable pipeline and gave downstream users a more consistent dataset for analysis and model development.

04 AIServe Team project AI feature integrated into a larger application Production AI integration
Python · FastAPI · PostgreSQL · Redis · Docker · REST APIs · LLM APIs

Problem. An AI capability needed to be integrated into an existing application rather than used as a standalone prototype. The system had to communicate with existing backend services, handle application-level data, and return results reliably within the larger product workflow.

Build. Worked with the development team to integrate the AI service behind a FastAPI layer and connect it with the application's existing APIs and database. Implemented request validation, response handling, logging, and failure paths around the model calls. Used Redis where short-lived state or repeated lookups could benefit from caching, and containerized the service for consistent deployment. Coordinated API contracts and integration points with other developers rather than treating the AI component as an isolated notebook or prototype.

Outcome. Turned the AI capability into a service that could participate in the application's normal backend workflow, with defined API boundaries, persistence, error handling, and deployment support.
